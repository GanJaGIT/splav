# Проектирование уровня $ARGUMENTS

Правила — §2.12, §2.13, §3.8 и §3.12 `docs/TZ.md`.

1. **Замысел.** Найди строку `$ARGUMENTS` в таблице §2.12: что уровень вводит, поле, `stepTicks`, ориентир заказов. Посмотри два соседних уровня: этот чуть сложнее предыдущего и вводит не больше одной новой сущности (LD-03).
2. **Поток.** Сложность почти целиком задаётся потоком — средним числом новых предметов в секунду (`среднее(perStep) / (stepTicks / 10)`) — против темпа игрока (§2.13). Не превышай предел LD-07 для главы. Чем выше нужный уровень заказа, тем больше предметов 1-го уровня нужной цепочки: для предмета уровня N нужно 2^(N−1) единиц. Лишние цепочки в весах — помехи: каждая цепочка сверх трёх усложняет уровень примерно как четверть добавочного потока.
3. **Пристани и препятствия.** Пристани ставь на берег не в нижний ряд, чтобы до них было удобно тянуть. Камни и коряги вводи так, чтобы они меняли решение: копили предметы в полосе, отрезали часть берега или требовали слияния рядом.
4. **Файл.** Запиши `levels/$ARGUMENTS.json` по формату §3.12, затем `npm run test -- levels` (схема).
5. **Проверка ботами.** `npm run sim -- $ARGUMENTS --bot all --seeds 20`. Нужно выполнить таблицу LD-01 для главы этого уровня (новичок, обычный, ловкий), LD-02 (длительность у обычного бота) и LD-07 (поток).
   - Не проходит — уменьши поток (длиннее `stepTicks` или `perStep` [1, 1] → [1, 2] при более длинном шаге: порции играются легче ровного потока), убери помеху из весов, освободи клетку берега.
   - Слишком легко (обычный бот в главах 2–3 проходит 20 из 20 быстрее чем за 1,5 минуты) — добавь заказ, камень или цепочку-помеху; поток поднимай последним, у него резкий порог.
6. **Плавность.** Сравни с соседними уровнями: доля побед обычного бота не падает больше чем на 5 из 20, кроме первого уровня главы (LD-03). Выбери как `seed` сид, на котором обычный бот (в главе 1 — новичок) прошёл уровень (LD-05).
7. **Тексты.** Название на ru и en — до 22 символов (LD-06): ключ `level.$ARGUMENTS.name` в оба файла i18n. Если уровень вводит новое — поле `intro` и карточка «Новое» в i18n (TUT-02). Если в подарок бустер — поле `gift`.
8. **Взгляд игрока.** Открой уровень через `window.__game`, запусти бота и сделай скриншоты на 360×640 и 1280×720. Поле читается, пристани и заказы видны, клетка не меньше 44 px (UI-10).
9. **Тесты и журнал.** `npm run test` — T-15 зелёный для уровня. Запиши в PROGRESS.md: уровень, поток, доли побед трёх ботов, среднюю длительность у обычного бота, что вводит. После изменения уровней глав 1–3 запусти `npm run balance`.

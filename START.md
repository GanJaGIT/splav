# Как вести «Сплав» через Claude Code

Инструкция для владельца. Claude Code эту инструкцию не исполняет — ему хватает `CLAUDE.md` и `docs/TZ.md`.

Концепция игры (для себя): https://claude.ai/code/artifact/6cb84b2e-3045-4a44-9989-6751fff639c9

## Что в комплекте

| Файл | Зачем |
|---|---|
| `docs/TZ.md` | Техническое задание: игра, правила симуляции реки, бот для проверки уровней, интерфейс, требования Яндекса, этапы с критериями приёмки |
| `CLAUDE.md` | Правила проекта. Claude Code читает его автоматически в каждой сессии |
| `docs/PROGRESS.md` | Журнал Claude: что сделано, какие решения принял, вопросы к тебе |
| `claude-setup/settings.json` | Разрешает npm-скрипты, тесты и git без вопросов; `git push` — только с подтверждением |
| `claude-setup/skills/` | Команды `/level-design`, `/yg-audit`, `/yg-release` |
| `claude-setup/agents/yg-moderator.md` | Независимая проверка «глазами модератора» перед отправкой |

## Один раз перед стартом

1. Установи Node.js LTS (с сайта nodejs.org) и Git (git-scm.com). Проверка в терминале: `node -v` и `git -v`.
2. Открой эту папку в Claude Code: в приложении Claude выбери папку `Splav` на рабочем столе, или в терминале `cd Desktop\Splav`, затем `claude`.
3. Папка `claude-setup` — это будущая служебная папка Claude Code `.claude` (удалённо её создать нельзя). При первом запуске Claude сам перенесёт её содержимое в `.claude` и попросит перезапустить сессию — просто закрой и снова открой Claude Code в этой папке. Можно и вручную: переименуй `claude-setup` в `.claude` (в Проводнике Windows введи имя `.claude.` с точкой в конце — точка в конце исчезнет).
4. Чтобы Claude реже спрашивал разрешения, включи режим, в котором правки файлов принимаются автоматически (`acceptEdits`), или `auto`, если он доступен на твоём тарифе.
5. Пока Claude пишет код, сделай свою часть в консоли Яндекс Игр (раздел ниже).

## Промпты по этапам

Отправляй один промпт на этап и дожидайся конца этапа.

**Этап 0 — каркас**

```
Прочитай CLAUDE.md (и выполни раздел «Первый запуск», если он ещё не сделан), docs/TZ.md и docs/PROGRESS.md. Выполни Этап 0 из ТЗ полностью и не начинай Этап 1. В конце покажи вывод npm run verify и обнови docs/PROGRESS.md.
```

**Этапы 1–5** — тот же текст, только с другим номером. Например:

```
Выполни Этап 1 из docs/TZ.md полностью и не начинай следующий. В конце покажи вывод npm run verify и обнови docs/PROGRESS.md.
```

**Режим «работай, пока не закончишь».** Команда `/goal` заставляет Claude продолжать, пока условие не выполнится:

```
/goal Этап 1 из docs/TZ.md выполнен: все его критерии приёмки выполнены, npm run verify завершился без ошибок и его вывод показан в чате, docs/PROGRESS.md обновлён, Этап 2 не начат. Остановись после 60 ходов.
```

**Плейтест**

```
Я поиграл в уровни 1–6. Замечания:
- …
- …
Исправь, прогони npm run verify и обнови PROGRESS.md.
```

**Если уровень слишком лёгкий или трудный**

```
/level-design c1-07
Уровень слишком лёгкий: прошёл без потерь за минуту. Сделай чуть сложнее.
```

**Релиз**

```
/yg-release
```

Затем:

```
Попроси агента yg-moderator проверить сборку и release/. Исправь блокеры и риски, потом снова запусти /yg-release.
```

## Что проверить самому после этапа

| Этап | Что сделать | На что смотреть |
|---|---|---|
| 0 | `npm run dev`, открыть адрес из терминала | Видна река с рябью, нет ошибок |
| 1 | Прочитать PROGRESS.md | Тесты T-01…T-14, T-16, T-17 зелёные; бот проходит первые уровни |
| 2 | Пройти уровни 1–4 на компьютере и телефоне (`npm run dev -- --host`, телефон в той же Wi-Fi сети) | Предметы легко тянуть пальцем, палец их не закрывает, река не слишком быстрая, слияние приятно «щёлкает» |
| 3 | Пройти главу 1, заглянуть в главы 2–3, построить что-нибудь в деревне | Сложность растёт плавно, хочется сыграть ещё один уровень, монет хватает на постройки, прогресс не теряется после перезагрузки |
| 4 | `npm run dev:yg` | Реклама-заглушка после уровня 6, звук и река останавливаются при сворачивании вкладки, «Река дня» открывается |
| 5 | Посмотреть всё в `release/` | Картинки красивые, тексты без ошибок, видео живое |

Главный вопрос на плейтестах: где было скучно, а где нервно. Честный ответ на него важнее любых технических замечаний.

На плейтестах Этапов 2 и 3 открой игру с `?dev=1` и посмотри счётчик «действий в секунду» после пары уровней. Сообщи это число Claude: по нему подстраиваются боты, которые проверяют сложность уровней (LD-08).

## Твоя часть в консоли Яндекс Игр

До Этапа 4:

- зарегистрироваться в консоли разработчика, оформить договор и самозанятость (если ещё не сделано);
- создать черновик игры «Сплав», чтобы получить её ID;
- в разделе «Реклама» включить стики-баннеры (телефон — внизу, компьютер — включить) и опцию «Использовать API для показа sticky-баннера»;
- включить автоматический полноэкранный режим, если такая настройка есть;
- создать два лидерборда: `stars` и `daily` (числовые, по убыванию).

Если договор позволяет покупки:

- добавить товары `no_ads` («Без рекламы», постоянный) и `boosters_10` («Набор бустеров», расходуемый);
- добавить свой логин в «Список логинов для тестовых покупок»;
- сказать Claude включить `features.iap` в `src/config.ts`.

Перед отправкой на модерацию — шаги из `release/UPLOAD.md`, который создаст `/yg-release`.

## Если что-то пошло не так

- `npm run verify` красный, и Claude не справляется за 2–3 попытки: «Остановись. Опиши проблему в PROGRESS.md и предложи два варианта решения».
- Claude сломал то, что работало: «Откати изменения к последнему коммиту, где verify был зелёным».
- Хочешь другой сеттинг, цепочки, баланс или название: скажи прямо. В §1.5 ТЗ указано, где что меняется.
- Модерация отказала: перешли Claude текст отказа и картинку из письма: «Вот отказ модерации. Исправь, прогони /yg-audit и /yg-release».

## Сроки

Этапы 0–5 занимают примерно 2–3 недели, если работать вечерами. Самые затратные по твоему времени — плейтесты на Этапах 2, 3 и 5.

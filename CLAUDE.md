# «Сплав» — правила проекта

Merge-головоломка для Яндекс Игр: река несёт предметы вниз, игрок сливает одинаковые, пока их не унесло, выполняет заказы жителей и отстраивает деревню. Полное ТЗ — `docs/TZ.md`, журнал работы — `docs/PROGRESS.md`. С владельцем (Артемий) общайся по-русски.

## Первый запуск

Если в корне проекта есть папка `claude-setup/`, а папки `.claude/` нет — сначала перенеси содержимое `claude-setup/` в `.claude/` (сохранив структуру: `settings.json`, `skills/`, `agents/`), удали `claude-setup/` и попроси владельца перезапустить сессию Claude Code, чтобы подхватились разрешения, навыки и агент. Только потом переходи к работе.

## Как работать

1. В начале каждой сессии прочитай `docs/PROGRESS.md` и разделы ТЗ для текущего этапа (таблица ниже).
2. Делай только текущий этап. Следующий — по команде владельца.
3. Маленькие шаги: изменение → тест → коммит. Сообщение коммита начинается с ID требования: `SIM-21: колонна предметов сдвигается целиком`.
4. Проверяй себя сам: тесты, запуск в браузере через Playwright, скриншоты (смотри их). Не говори «готово», пока `npm run verify` не зелёный.
5. Неясно — выбери самый простой вариант, не нарушающий требований Яндекса, и запиши решение в PROGRESS.md → «Решения». Нужен владелец — PROGRESS.md → «Вопросы владельцу», и продолжай остальную работу.
6. В конце сессии обнови PROGRESS.md: что сделано (с ID), что дальше, проблемы.

## Архитектура — не нарушать

- `src/sim` — чистый TypeScript: без Phaser, DOM, `window`, `Date`, `Math.random`. ГПСЧ — mulberry32 в состоянии (SIM-24). Детерминизм и инварианты — SIM-40, SIM-41.
- Интерфейс, бот и тесты меняют игру только действиями (`grab`, `drop`, `cancel`, `booster`, `continue`, §3.5). Отрисовка читает состояние и `events`.
- `src/platform` — единственное место, где есть `YaGames` и `ysdk`. Остальной код работает с интерфейсом `Platform`.
- Тексты интерфейса — только в `src/i18n/*.json`. Контент (цепочки, постройки, бустеры, уровни) — только JSON.
- Поле рисует Phaser 4, интерфейс и деревня — DOM, CSS и SVG поверх него.
- `GameplayState` — единственный, кто вызывает `GameplayAPI.start()` и `stop()`. `AudioService` — единственный, кто включает звук.

## Правила, которые легко нарушить

- Река не должна течь, когда игрок не смотрит: любая пауза, уход из вкладки, `blur`, реклама, ресайз — симуляция стоит, открыта «Пауза» (YG-04, YG-05).
- Каждый уровень обязан проходиться ботом без бустеров (LD-01, LD-05). Уровень, который бот не проходит, не коммитится.
- `LoadingAPI.ready()` — ровно один раз, когда первый экран интерактивен.
- Полноэкранная реклама — только сразу после «Дальше» или «В деревню», начиная с уровня c1-06, не чаще раза в 180 секунд. Никогда посреди уровня и по таймеру.
- Rewarded — только по кнопке, где видно, что будет реклама и что дадут. Награда — в `onRewarded`.
- Стики-баннер — только в деревне, в уровне скрыт (YG-12).
- Клавиатура — только `event.code`. Нет контекстного меню, выделения текста, прокрутки страницы, `alert`/`confirm`.
- Прогресс сохраняется сразу после изменения и без авторизации.
- Пути относительные; в архиве `index.html` в корне; имена файлов латиницей без пробелов.
- Никаких внешних ссылок и запросов, сторонней рекламы, интерактивного ИИ.

## Команды

Создаются на Этапе 0: `npm run dev`, `dev:yg`, `test`, `e2e`, `verify`, `sim`, `balance`, `bench`, `art`, `build`, `zip`, `promo`.

## Документация

- Яндекс Игры: https://yandex.ru/dev/games/doc/ru/llms.txt — перед работой с SDK читай нужную страницу, не пиши по памяти. Ссылки на ключевые страницы — §12 ТЗ.
- Phaser 4: официальные skills в `.claude/skills/` (копируются на Этапе 0). Не используй API Phaser 3, которых нет в v4.

## Навыки и агенты

- `/level-design <id>` — создать или настроить уровень с проверкой ботом.
- `/yg-audit` — проверка по требованиям Яндекса (с Этапа 4).
- `/yg-release` — релизный пакет (Этап 5).
- Агент `yg-moderator` — независимая проверка перед отправкой на модерацию.
